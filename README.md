# Akvilon InHome — интеграция для Home Assistant

Интеграция ЖК «Reka» (застройщик Аквилон) для Home Assistant.
Подключается к серверу здания по UDP-протоколу и предоставляет:
камеры, калитки/домофоны, счётчики, статус сервера.

> ⚠️ Неофициальная интеграция. Протокол восстановлен реверс-инжинирингом из
> Android-приложения `inHome` (v4.0.229). Используйте на свой риск.

---

## Требования

- Home Assistant 2024.1.0 или новее
- [HACS](https://hacs.xyz) (Home Assistant Community Store) для установки

## Установка через HACS (рекомендуется)

1. Откройте **HACS** в Home Assistant.
2. Пункт меню ⋮ (правый верхний угол) → **Custom repositories**.
3. Вставьте URL: `https://github.com/Gakuzi/akvilon_home_hacs`
4. Тип: **Integration** → **Add**.
5. Интеграция появится в списке HACS → **Аквилон InHome**.
   - Для стабильной версии выберите канал **Stable**.
   - Для тестирования новых функций — канал **Beta**.
6. Нажмите **Download**, затем перезапустите Home Assistant.
7. Настройте интеграцию: Настройки → Устройства и службы → Добавить →
   введите QR-строку или параметры HOST/PORT/DEVICE_ID/SERVER_ID/PASS.

### Ручная установка

Скопируйте папку `custom_components/akvilon_home/` в ваш каталог
`config/custom_components/`, перезапустите HA и выполните шаг 7 выше.

| Канал | Источник | Git-тег | Назначение |
|-------|----------|---------|-----------|

## Настройка (сеть, квартира)

Интеграция принимает параметры из QR-строки приложения или вручную:

| Параметр | Описание | Пример |
|----------|----------|--------|
| `host` | Адрес сервера здания | `127.0.0.1` |
| `port` | UDP-порт сервера | `19090` |
| `device_id` | ID устройства (квартиры) | `0:0` |
| `server_id` | ID сервера | `0:0` |
| `token` / `_PASS` | Секрет подписи (ASCII) | `PASS_PLACEHOLDER` |

## Возможности

- **Камеры** — до 69 IP-камер комплекса с именами.
- **Калитки** — кнопки открытия проходов/дверей.
- **Домофоны** — калитки с привязанной камерой = домофон (8 шт).
- **Счётчики** — ГВС, ХВС, отопление, электричество (+ тарифы день/ночь для эл-ва).
- **Статус** — бинарный онлайн-индикатор сервера.

## Не реализовано (известные ограничения)

- **Живой видеопоток (RTP)** камер не отображается: сервер отдаёт параметры
  потока только в невоспроизводимой пока последовательности. Требуется pcap
  реального приложения при просмотре камеры. Следите за веткой `feature/video-stream`.

## Выпуск релизов и каналы (для разработчиков/агентов)

Репозиторий публикуется через HACS. Для управления каналами используются
git-ветки и теги:

| Канал HACS | Ветка | Git-тег | Что попадает |
|------------|-------|---------|--------------|
| Stable      | `main`    | `v*`           | проверенные релизы |
| Beta        | `develop` | `v*-beta*`     | свежие функции/исправления |

### Собрать и опубликовать релиз

Все операции на Raspberry Pi. Исходники берутся из рабочего dev-репозитория
`/home/pi/homeassistant/custom_components/akvilon_home`.

```bash
# Стабильный релиз (тег v1.1.0 на main)
/home/pi/akvilon_home_hacs/scripts/release.sh 1.1.0

# Бета-релиз (тег v1.2.0-beta1 на develop)
/home/pi/akvilon_home_hacs/scripts/release.sh 1.2.0 --beta
```

Скрипт копирует исходники в HACS-структуру, обновляет версию в manifest.json,
коммитит и пушит с тегом. HACS увидит новый релиз по тегу.

### Разделение frontend / backend (команда разработки)

Проект можно вести параллельно нескольким агентам, не мешая друг другу:

| Направление      | Ветки                                | Файлы |
|------------------|--------------------------------------|-------|
| Backend (ядро)   | `feature/*-core`, `develop`           | protocol.py, coordinator.py, __init__.py, config_flow.py |
| Frontend (UI)    | `feature/*-frontend`                  | poetry: dashboard/lovelace, кастомные карточки |
| Интеграция       | `develop` → `main`                    | сборка и проверка |

Правила параллельной работы — в [AGENTS.md](custom_components/akvilon_home/AGENTS.md)
(разделы 9.4–9.6). Ключевое: каждый агент работает в своей `feature/*`-ветке,
никаких прямых коммитов в `main`, слияние — через `develop` после проверки.

## Индикация состояния и статусы сервера

При настройке интеграции мастер показывает этап **проверки соединения с сервером**.
Возможные статусы и что они означают:

| Индикатор | Значение | Что делать |
|-----------|----------|------------|
| 🟢 **Доступен** | Сервер здания отвечает, соединение установлено | Ничего, можно выбирать устройства |
| 🟡 **Нет данных** | Сервер доступен, но не вернул список устройств | Проверьте ключ/доступы, повторите позже |
| 🔴 **Недоступен** | Не удалось установить соединение с сервером | Проверьте сеть (Wi-Fi/интернет), сервер временно отключён |

В Home Assistant также создаётся сущность **binary_sensor** «Сервер здания онлайн»
(зелёная/красная иконка), которая показывает, доступен ли сервер в последние
30 минут.

## Проверка доступа к серверу вручную

Если интеграция пишет, что сервер недоступен, но приложение на телефоне
работает, проверьте с компьютера доступ по UDP:

OK

Отсутствие ответа означает, что сервер здания сейчас не отвечает — это не
проблема интеграции.
