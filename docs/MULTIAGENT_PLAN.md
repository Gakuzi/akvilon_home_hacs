## 3. Порядок работы (согласован владельцем: план → субагенты)

1. **Владелец утверждает** этот план (или правит).
2. Основной агент (я) фиксирует текущую работу (done — 0216ee6).
3. **Субагенты работают автономно** каждый в своей `feature/*`, параллельно.
   Наработки передают мне; не блокируют друг друга.
4. На каждый PR/branch — гейты: `qa-gatekeeper` (тесты+покрытие+секреты),
   затем `doc-gatekeeper` (README/CHANGELOG/ADR/docstring).
5. Я свожу ветки в `main` после зелёных гейтов; владелец — финальное одобрение
   релиза (release-orchestrator).

```
feature/entities-device-energy ─┐
feature/video-go2rtc            ├── сведение в main ──> v1.8.0 (релиз)
feature/core-stability          │      (после гейтов)
feature/dashboard-views         ├── (qa-gate + doc-gate на каждый)
feature/release-pipeline        ┘
```

## 4. Обязательные гейты (не пропускаем)

- Код — в своей `feature/*`-ветке, НЕ в `main`/`develop`.
- Документация — ДО коммита (доки «вместе с кодом»).
- Коммиты — Conventional Commits: `type(scope): описание`.
- Тесты зелёные, покрытие >= 60% (`qa-gatekeeper`).
- Секреты не протекают (`qa-gatekeeper`).
- README/CHANGELOG/ADR/docstring актуальны (`doc-gatekeeper`).
- Пробел в чём-то — явный waiver `Doc-Exempt: <причина>`.
- Релиз — только с одобрения владельца (`release-orchestrator`).
