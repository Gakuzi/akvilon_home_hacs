# ADR-003: Корректное отображение счётчиков в панели «Энергия»

- **Статус:** принято
- **Дата:** 2026-10-10
- **Ветка-источник:** `fix/energy-meters-display`

## Контекст

Панель «Энергия» Home Assistant неправильно отображала счётчики Аквилон:
датчики либо не находились («Не удалось определить объект»), либо отклонялись
(«Класс устройства отличается от ожидаемого»). При разборе выяснилось несколько
независимых причин:

1. **Статичные сенсоры.** `AkvilonMeterSensor`/`AkvilonMeterTariffSensor` держали
   словарь метера из момента первой регистрации, не перечитывали хаб и не
   обновляли состояние — показания и `device_class` «застывали».
2. **`device_class` зависел от `resourceType` сервера**, который реальные приборы
   присылают **не всегда** (в `const.METERS` его нет даже для электричества).
   При его отсутствии `device_class` был `None` — Энергопанель видела сенсор без
   класса и отклоняла его как «не тот класс устройства».
3. **Ненадёжный резолв entity_id** в `energy.py`: `_find_entity` возвращал «первый
   сенсор, содержащий подстроку», из-за чего базовый счётчик дня мог «уползти» на
   тариф-_noch, а в панель могли попадать сенсоры-суррогаты (`_2`, `_3`).
4. **Отопление добавлялось в панель как источник.** Энергопанель HA не
   поддерживает теплосчётчики (Гкал) как источник — такой сенсор отклонялся.
5. **Битые/устаревшие `energy_sources`** оставались в `.storage/energy` после
   пересоздания счётчиков, из-за чего в панели висели записи о несуществующих
   объектах.

## Решение

### `sensor.py` — «живые» сенсоры
- Конструктор принимает `hub`; сенсор хранит только `device_number` и label.
- `_live()` каждый раз читает актуальный метер через `hub.meter_by_number()`.
- `async_added_to_hass` запускает фоновый poll (~60 с): перечитывает метер и
  вызывает `async_write_ha_state()`, задача отменяется в `async_will_remove_from_hass`.
- `device_class` определяется детерминированно по **единицам измерения**
  (`_meter_device_class`): м³ → `water`, кВт·ч/Гкал → `energy`, `resourceType` —
  только запасной путь, не единственный.

### `coordinator.py` — lookup
- Добавлен `hub.meter_by_number(device_number)` для поиска актуального метера.

### `energy.py` — надёжная интеграция в панель
- entity_id резолвятся через **entity_registry по `unique_id`** (`_uid_to_eid`,
  `_resolve_meter_eids`), fallback — скан состояний. Это гарантирует, что в
  панель попадают именно T1/T2 базового счётчика, а не суррогаты.
- Добавлена чистая классификация счётчика `classify_meter` (единицы →
  resourceType → имя): `electricity` / `cold_water` / `hot_water` / `heating`.
- **Отопление (`heating`) не добавляется** в панель — HA не поддерживает Гкал.
- При переконфигурации источники воды/грид Аквилон, ссылающиеся на удалённые
  сенсоры или уже не наши, **удаляются** (`_is_akvilon_entity`, `_split_flows`),
  чужие источники сохраняются.

## Последствия

- Показания и классы счётчиков обновляются в рантайме без рестарта интеграции.
- Панель «Энергия» показывает электричество (день/ночь) и воду корректно;
  тепло больше не отклоняется.
- Резолв по `unique_id` устойчив к пересозданию сущностей с суффиксами `_2`.
- Осложнение: `energy.py` теперь зависит от `homeassistant.helpers.entity_registry`,
  импортируемого лениво (внутри `async_setup_energy`), чтобы чистые функции
  продолжать тестировать голым Python.
