# ADR-001: Покадровый захват видео камер через UDP/RTP

- **Статус:** принято
- **Дата:** 2026-10-08
- **Ветка-источник:** `feature/video-stream` → `feature/release-1.7.0`

## Контекст

Интеграция Akvilon InHome должна показывать камеры видеонаблюдения жилого
комплекса в Home Assistant. Прямой RTSP/RTMP-доступа к камерам нет: видео идёт
через UDP-прокси сервера здания (`<адрес_сервера>:19090`). Требовалось понять,
какой протокол и последовательность пакетов использовать, чтобы получить
реальный кадр.

## Решение

Принят **покадровый захват** через UDP/RTP (а не непрерывный поток):

1. `openCamera` (канал `0x30401`) → сервер отвечает `cameraSettings`
   (канал `0x2030401`): `videoHost`, `videoPort`, `videoToken`, `spropParameter`.
2. На `videoHost:videoPort` отправляется подписочная UDP-датаграмма
   `b"\x00\x00" + videoToken` — это ключевой пакет запуска потока
   (найден по pcap приложения inHome; без префикса `\x00\x00` старт не работает).
3. Сервер стримит RTP/H.264 на тот же клиентский UDP-порт. Модуль `rtp_stream.py`
   собирает IDR-кадр (одиночные NAL / STAP-A / FU-A) и декодирует в JPEG через
   ffmpeg (`-f h264 -f mjpeg`).
4. `hub.camera_frame(cam_id, timeout)` выполняет весь путь в executor (не на
   event loop HA). После захвата отправляется `closeCamera`, чтобы не копить
   лимит активных видео-сессий на сервере.

## Почему так (альтернативы)

- **Непрерывный поток (RTSP/MPEG-TS)** потребовал бы постоянно держать UDP-сессию
  и гнать все камеры — нагрузка на сервер здания и на Pi. Не выбрано на первом
  этапе (см. «Следующий шаг»).
- **Прямой RTSP** к камерам недоступен — только UDP-прокси сервера.
- Покадровый захват достаточно для `camera.async_camera_image()` (превью) и для
  веб-панели viewer (снимки по таймеру), не блокируя event loop.

## Следующий шаг

- Непрерывный поток (RTSP/MJPEG для HA `stream`) можно добавить на той же
  основе `rtp_stream.py` (например через go2rtc), если понадобится живое окно
  без обновления по таймеру.

## Последствия

- `camera.async_camera_image()` возвращает реальный JPEG за 1–2 с.
- Все сетевые/блокирующие операции выполняются в executor — HA не зависает.
- Требуется `ffmpeg` (есть в контейнере HA).
