# ADR-003: Живой интерком через go2rtc + WebRTC + Frigate-детекцию

- **Статус:** принято
- **Дата:** 2026-10-11
- **Ветка:** `feature/go2rtc-webrtc`

## Контекст

Интеграция Аквилон InHome уже умеет покадровый захват и непрерывный живой поток
через shared RTP-сессию (ADR-001, ADR-002). Для **домофона** этого недостаточно:
пользователь хочет *живое* видео с низкой задержкой и автоматическое уведомление
«кто-то у двери». Двумя внешними инструментами решаются обе задачи:

- **go2rtc + WebRTC (AlexxIT)** — живой поток с задержкой ~0.1–0.5 с для карточки
  `custom:webrtc-camera`;
- **Frigate** — AI-детекция людей, создающая `binary_sensor.<cam>_person` и push
  «кто-то у двери».

Оба инструмента — **внешние аддоны/процессы** (64-битный хост), их решение
принимает владелец. Задача этой ветки — написать код интеграции, который даёт
пользователю *готовую конфигурацию и сервисы* для этой связки, НЕ тянуть go2rtc и
Frigate в HACS-копию и не ломать загрузку/релоад HA при их отсутствии.

## Ограничение (критично)

Видео Аквилон — **RTP/H.264 по UDP** (НЕ RTSP). Прямого RTSP-входа нет, и go2rtc
«из коробки» не примет сырой RTP с нашей подписью `b"\x00\x00"+videoToken`
(поток запускается только после openCamera → cameraSettings). Поэтому:

1. **`exec:`-источник** `go2rtc_proxy.py`: мост сам открывает камеру
   (openCamera → cameraSettings), шлёт подписочный пакет, читает RTP и пишет сырой
   H.264 (annexb) в stdout — то, что go2rtc принимает как источник видео.
2. **`ffmpeg:`-источник** `udp://host:port?timeout=…#video=copy#hardware` — фолбэк
   для случая, когда RTP-поток уже запущен (например viewer-ом).

## Решение

### go2rtc.py
Чистый модуль (без HA на верхнем уровне), генерирующий конфигурацию и URL:

- `build_ffmpeg_udp_cmd` / `build_exec_cmd` — команды `ffmpeg:` / `exec:`;
- `build_stream_config` / `build_config` — YAML-блок `streams:` для go2rtc.yaml;
- `webrtc_url` / `api_stream_url` — адреса для карточки `custom:webrtc-camera`;
- сервисы `akvilon_home.go2rtc_config`, `go2rtc_stream_url`, `go2rtc_proxy_cmd`.

### go2rtc_proxy.py
Самодостаточный исполняемый мост для `exec:`-источника go2rtc. Импортирует
`protocol.py`/`rtp_stream.py` (они не требуют HA), работает вне event loop.

### frigate_detect.py
Платформа (по паттерну `binary_sensor`):

- `FrigateDetectConfig` — чистая абстракция: метки детекции, событийный эндпоинт
  `api/events`, YAML-блок детектора `detect:` для go2rtc/Frigate;
- `FrigatePersonSensor` — `binary_sensor` «человек у двери» (привязка к камере);
- `FrigateEventSubscriber` — фоновая HTTP-подписка на события Frigate: включает
  сенсор и шлёт в hass.bus событие `akvilon_home_person_detected` (автоматизация
  ловит его и делает push). Grace-период `PERSON_GRACE_S` снимает присутствие.

### config_flow.py / __init__.py
- Опции go2rtc/Frigate добавлены в entry.data (по умолчанию выключены) и в
  OptionsFlow (`akvilon_home` → Параметры), и в миграцию entry.
- Платформа `frigate_detect` добавлена в `PLATFORMS`; `__init__.py` регистрирует
  сервисы go2rtc и (через forward_entry_setups) платформу заметания.

## Альтернативы

- **Тянуть Frigate/go2rtc в HACS-копию** — отвергнуто: это внешние тяжёлые сервисы,
  интеграция даёт лишь контракт и настройку. Присутствие/отсутствие go2rtc/Frigate
  не влияет на загрузку HA.
- **Использовать только MJPEG-viewer (ADR-002)** — работает, но задержка выше и нет
  детекции. go2rtc/Frigate дают желаемый UX для интеркома, а MJPEG остаётся фолбэком.

## Последствия

- Пользователь получает готовые команды и YAML для go2rtc/Frigate через сервисы и
  документацию; простые вставки в свою конфигурацию go2rtc/Frigate.
- При выключенных опциях интеграция работает как раньше (без единой зависимости).
- Новые модули всё делают в executor/фоновых потоках, не блокируя event loop.
- `binary_sensor.<cam>_person` и событие `akvilon_home_person_detected` позволяют
  автоматизациям оповещать о человеке у двери (push).

## Ограничение

Frigate/ft-детекция требует 64-битный хост и работает только при установленном
Frigate с настроенным детектором person; без него сенсоры просто не создаются
(опция выключена). Реальная калибровка порогов — задача владельца.
