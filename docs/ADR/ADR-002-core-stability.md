# ADR-002: Устойчивость UDP-ядра к реальным условиям сети

- **Статус:** принято
- **Дата:** 2026-10-10
- **Ветка-источник:** `feature/core-stability`

## Контекст

UDP-протокол к серверу здания по своей природе ненадёжен: возможны одиночная
потеря датаграмм, редкие ответы и таймауты. При этом сервер Аквилон ведёт себя
специфично:

- на один GET-список канала отвечает **только раз за UDP-сессию** и отдаёт лишь
  ~18 JSON-тел (при объявленных 69 камерах) — полный банк надо собирать
  несколькими свежими сессиями, накапливая;
- продолжает слать части списка **только после ACK** на предыдущий пакет
  (cmd=2, flag|=0x02);
- при недоступности «молчит» (timeout), а не ошибкается.

Требование проекта №1 — стабильность: изменения не должны ломать загрузку/релоад
Home Assistant и не должны «ложно» показывать онлайн-статус.

## Решение

### `protocol.py`
1. **`get_list` — накопление и повтор по сессиям.**
   id из заголовков объединяются по сессиям (`known_ids` — dict, не last-wins),
   тела накапливаются в `seen`. Объявленный `count` хранится как максимум по
   сессиям. Если за `sessions` раундов собрать все тел не удалось — возвращаем
   лучшее, что есть, и **обязательно логируем предупреждение** (неполный банк
   не отдаётся молча).
2. **Retry GET-ALL** (`_get_header`, параметр `retries`) — при одиночной потере
   ответа запрос повторяется в той же сессии, прежде чем крутить свежую.
3. **Повтор проспанной порции** (`_collect_bank`) — недостающие id внутри сессии
   запрашиваются второй раз (устойчивость к одиночной потере) перед сменой сессии.
4. **ACK не теряется.** Читающий поток ACK-ит каждый входящий пакет; при сбое
   `sendto` делается одна повторная попытка.
5. **Сериализация отправки.** Все записи в сокет идут через `_send_lock`
   (безопасный инкремент `seq` + целостность датаграмм между ридером, keepalive
   и основным потоком). Повышает устойчивость при перегрузке.
6. **Keepalive-таймер подписки 0x200** (`_start_keepalive`, ~15 с) — фоновая
   подписка держит сессию живой на время долгих GET-опросов; гейтится по
   `_running`, останавливается при `close()`/смене сессии.
7. **Бюджет времени (`get_list`)** — общее время ограничено `timeout`, цикл по
   сессиям не «висит» на полуживом сервере.

### `coordinator.py`
- `refresh()` **никогда не бросает исключение**: каждый банк в try/except, нижний
  предохранитель на весь метод. Возвращает `bool` (получен ли хоть один банк).
- `_last_ok`/`_online` обновляются **только при реальном приёме данных**
  (`client._last_rx > 0`), а не до опроса — онлайн-сенсор не «врёт» при падении банка.
- Добавлены `hub.is_online` и `hub.last_refresh_error` для диагностики.

## Почему так (альтернативы)

- **Синхронный retry в одном потоке** — после каждого шага повторяем запрос;
  проще и детерминированнее, чем полноценный стейт-машина с очередями.
- **Новый сокет на сессию** — сервер отвечает на GET только раз за UDP-сессию,
  поэтому «свежая сессия» при сбое — единственный рабочий способ получить
  остаток списка; это было уже реализовано и сохранено (не убрано).
- **Не использовать `_send_lock`** оставлял бы гонки на `seq` между keepalive и
  `get_list`; блокировка нереентрабельна, поэтому пакет собирается **вне**
  блокировки (иначе дедлок с `_next_seq`), а шлётся под ней.

## Последствия
- Сущности не «падают» при недоступности сервера; сбор всех камер (69) устойчив.
- Сигнатуры публичных методов (`get_list`, `subscribe`, `register`, `open_gate`,
  `refresh`) не менялись; правки — внутри реализации и защищены тестами.
- Покрытие ядра одевается «стресс»-тестами (`tests/test_core_stability.py`).
