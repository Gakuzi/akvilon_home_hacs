# RELEASE_POLICY.md — Политика публикации релизов Akvilon InHome

> Как принимаются изменения, доводится разработка и что попадает в публичные
> релизы. ОБЯЗАТЕЛЬНО к прочтению владельцем и агентами, имеющими право на release.

## 1. Два репозитория (приватный и публичный)

Разработка и публикация разделены на ДВА репозитория:

| | Приватный (dev) | Публичный (HACS) |
|---|---|---|
| URL | `git@github.com:Gakuzi/akvilon_home.git` | `https://github.com/Gakuzi/akvilon_home_hacs` |
| Путь на Pi | `/home/pi/homeassistant/custom_components/akvilon_home` | `/home/pi/akvilon_home_hacs` |
| Доступ | приватный (только команда/агенты с доступом) | публичный (HACS скачивает релизы) |
| Назначение | разработка, обкатка, тесты | выпуск чистых релизов в проде |
| Личные данные | допустимы (закрытый репозиторий) | ЗАПРЕЩЕНЫ (см. §3) |

**Правило:** публичный репозиторий получает ТОЛЬКО через скрипт `sanitize.sh`
(очистка личных данных) + `release.sh` (релиз). Руками в публичный репо код
не копируется.

## 2. Обкатка на приватном, выпуск в публичный

Цикл разработки:

```
агент -> feature-ветка -> merge в develop (приватный)
  -> обкатка: запуск HA, проверка журнала, тесты
  -> НЕЛЬЗЯ сразу в публичный
  -> sanitize.sh (вычистить личные данные) -> release.sh (тег/релиз)
  -> публичный HACS-репозиторий -> HACS уведомит об обновлении
```

1. Агенты работают в приватном репозитории на своих `feature/*`.
2. Когда задача готова и проверена — вливается в приватный `develop`.
3. Владелец проверяет готовность к релизу (см. §4).
4. Формируется релиз: `sanitize.sh` чистит данные, `release.sh` тегирует.
5. Публичный репозиторий получает чистый код; HACS раздаёт его.

## 3. Что НЕЛЬЗЯ публиковать (очистка обязательна)

Перед любой публикацией `sanitize.sh` заменяет на плейсхолдеры:

| Личное/секретное | Пример |
|---|---|
| IP сервера здания | `127.0.0.1` |
| DeviceID квартиры | `0:0` |
| ServerID | `0:0` |
| Сессионный пароль (PASS) | `PASS_PLACEHOLDER` |
| SUID/ключ подписи | `fec8df...` (полный ключ) |
| Видео-токен | `token_placeholder` |
| Имена квартиры/жильцов | «Квартира 8», ФИО |
| Реальные имена камер-адресов жителей | — (заменяются обезличенно) |

После `sanitize.sh` в публичном репозитории НЕ должно оставаться реальных
секретов. Скрипт проверяет остатки и сообщает «чисто» или список.

## 4. Принятие решения о включении в релиз (checklist)

Когда фича готова к релизу, пройти все пункты:

- [ ] Код проверен: `python3 -m py_compile *.py` — нет ошибок.
- [ ] HA запускается после установки: `docker restart homeassistant`.
- [ ] В журнале нет ошибок интеграции: `docker logs homeassistant | grep -i akvilon`.
- [ ] Сущности корректно создаются (камеры/калитки/счётчики/домофоны).
- [ ] Изменения слиты в приватный `develop` и он стабилен.
- [ ] `sanitize.sh` отработал: публичная копия не содержит секретов.
- [ ] Версия проставлена в `manifest.json` соответствует тегу релиза.
- [ ] Release notes (список изменений) составлены.

Только после всех `[x]` релиз публикуется.

## 5. Версии и каналы

| Тег | Канал | Когда |
|-----|-------|-------|
| `vX.Y.Z` | Стабильный | Проверенный, стабильный код |
| `vX.Y.Z-betaN` | Бета | Новые функции для тестирования |

- Чётные/малые изменения — `vX.Y.Z` (патчи/фиксы).
- Крупные фичи — поднимать `Y` или `Z`.
- Бета-релизы идут в `develop` (HACS Beta-канал), стабильные в `main`.

## 6. Роли

- **Владелец (Gakuzi)** — принимает решение о выпуске, имеет право на release.
- **Агенты-разработчики** — работают в приватном репо, НЕ публикуют сами,
  только готовят feature/develop.
- **Агент-релизер** (если делегировано) — исполняет sanitize + release по
  этому документу, только с одобрения владельца.

## 7. Если обнаружили утечку данных

1. Немедленно `git revert`/удалите секрет из публичного репо.
2. `git push --force` не рекомендуется; при необходимости — согласуйте с владельцем.
3. Поверните секреты (смените PASS/token в настройках интеграции), если полный
   секрет утёк.
4. Добавьте в `sanitize.sh` новое правило очистки.
5. Внесите этот случай в историю для предотвращения повтора.
