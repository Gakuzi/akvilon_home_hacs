# Akvilon InHome — Home Assistant integration

Интеграция Аквилон InHome для Home Assistant (Raspberry Pi, хост `klim`).
UDP-протокол к серверу здания. Даёт владельцу квартиры: камеры видеонаблюдения,
калитки/домофоны, счётчики и онлайн-статус сервера.

## Ветки
- `main` — стабильная рабочая версия
- `develop` — интеграционная ветка разработки (общая точка сборки)
- `feature/video-stream` — рабочий видеопоток камер (RTP/H.264), готово к слиянию
- `feature/domofon` — входящий вызов домофона (push-listener + камера + действия)
- `feature/cleanup-entities` — задача: очистить дубли сущностей `_2`

## Структура
- `protocol.py` — UDP-клиент (подписка, регистрация, GET-списки, open_gate, openCamera)
- `coordinator.py` — `AkvilonHub`: загрузка камер/калиток/счётчиков/домофонов, `camera_frame`
- `camera.py` — платформа камер; `async_camera_image` — отдаёт кадр через RTP-приёмник
- `rtp_stream.py` — UDP/RTP-приёмник (H.264): сборка IDR и декод кадра в JPEG
- `button.py` — кнопки открытия калиток
- `sensor.py` — счётчики и состояние калиток
- `binary_sensor.py` — онлайн-статус сервера (+ входящий вызов домофона в feature/domofon)
- `config_flow.py` — мастер настройки (QR-строка)
- `const.py`, `manifest.json`, `services.yaml`, `strings.json` — константы и метаданные

## Видеопоток камер (работает)

С версии **1.7.0** интеграция умеет получать живой кадр с камер видеонаблюдения
через RTP-видеопоток (H.264). Видео идёт по UDP напрямую от сервера здания.

### Как это устроено (кратко)
1. `openCamera` на канал `0x30401` → сервер присылает `cameraSettings`
   (канал `0x2030401`): `videoHost`, `videoPort`, `videoToken`, `spropParameter` (SPS/PPS).
2. На `videoHost:videoPort` отправляется UDP-датаграмма `\x00\x00` + `videoToken`
   — это запускает RTP-поток (H.264, payload 96-127).
3. `rtp_stream.py` слушает UDP-порт, собирает IDR-кадр (одиночные NAL / STAP-A /
   FU-A), подставляет SPS/PPS и декодирует в JPEG (через ffmpeg).
4. `camera.py` (`async_camera_image`) запускает это в executor — event-loop HA
   не блокируется. Карточка камеры показывает живой кадр по запросу.

Подробности протокола — в `VIDEO_PLAN.md`.

### Ограничения
- Отдаётся **одиночный кадр по запросу** (снимок), а не непрерывный поток
  (`stream_source` не включён). Для зацикленного видео используйте автоматизации
  или сторонний `stream`-провайдер.
- `videoPort` у каждой камеры свой; сервер ждёт ровно датаграмму `\x00\x00`+token.
- Декод кадра требует ffmpeg в системе HA.
