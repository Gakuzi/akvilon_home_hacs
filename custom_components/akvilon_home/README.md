# Akvilon InHome — Home Assistant integration

Интеграция Аквилон InHome для Home Assistant (Raspberry Pi, хост `klim`).
UDP-протокол к серверу здания `127.0.0.1:19090`.

## Установка

1. Установите интеграцию через [HACS](https://hacs.xyz) → «Custom repositories»,
   укажите URL репозитория и выберите тип **Integration**, либо скопируйте папку
   `custom_components/akvilon_home/` в `config/custom_components/`.
2. Перезапустите Home Assistant.
3. Настройки → Устройства и службы → «Добавить интеграцию» → **Аквилон InHome**.

## Настройка

Мастер настройки состоит из двух шагов:

1. **Ключ подключения.** Вставьте строку подключения/QR от приложения застройщика
   (содержит HOST, PORT, DEVICE_ID, PASS, SERVER_ID). После ввода нажмите «Продолжить».
2. **Проверка соединения и загрузка.** Интеграция проверяет доступность сервера
   здания и автоматически загружает все найденные устройства — камеры, калитки,
   домофоны, счётчики. Результат (соединение установлено / нет) показывается
   понятным сообщением на русском языке.

После настройки все устройства появляются в Home Assistant автоматически,
создаётся дашборд «Аквилон» и доступна веб-панель камер (сервисы
`start_viewer` / `stop_viewer`).

## Возможности

- **Камеры** — до 69 IP-камер комплекса с именами. Живой кадр по запросу через
  UDP/RTP (`openCamera` → `cameraSettings` → подписочный пакет → H.264 → JPEG).
- **Веб-панель камер** (`viewer`) — локальный HTTP-сервис (порт 8090 по
  умолчанию) с сеткой всех камер, снимками по запросу и живым MJPEG для
  выбранной. Управляется сервисами `start_viewer` / `stop_viewer`.
- **Авто-панель «Аквилон»** — Lovelace-дашборд создаётся автоматически при
  настройке и удаляется при удалении интеграции. Виды повторяют приложение
  InHome: **Обзор / Камеры / Калитки / Счётчики / Домофон / Киоск**. Панель
  построена ТОЛЬКО штатными карточками HA (`vertical-stack`, `picture-entity`,
  `entities`, `grid`, `tile`), без custom JS-карточек — работает в любом
  браузере. Пустые виды (например, домофонов на сервере 0) скрываются.
- **Калитки/домофоны** — кнопки открытия проходов и дверей.
- **Счётчики** — ГВС, ХВС, отопление, электричество (+ тарифы день/ночь).
- **Тарифы** — парсер цен тарифов (`tariffs.py`): каноническая таблица региона
  по умолчанию (Архангельск) и нормализация пользовательского ввода для блока
  «Энергия».
- **Статус** — бинарный онлайн-индикатор сервера.

## Структура

- `protocol.py` — UDP-клиент (подписка, регистрация, GET-списки, open_gate,
  openCamera/closeCamera, отправка видео-токена)
- `coordinator.py` — `AkvilonHub`: загрузка камер/калиток/счётчиков/домофонов,
  `camera_frame()` для захвата JPEG-кадра через RTP
- `rtp_stream.py` — приём и декод H.264 RTP-потока камер (сборка IDR-кадра,
  декод в JPEG через ffmpeg)
- `camera.py` — платформа камер (кадр по запросу через `hub.camera_frame`)
- `viewer.py` — веб-панель камер (HTTP-сервер)
- `dashboard.py` — авто-дашборд Lovelace
- `button.py` — кнопки открытия калиток
- `sensor.py` — счётчики и состояние калиток
- `binary_sensor.py` — онлайн-статус сервера
- `config_flow.py` — мастер настройки
- `tariffs.py` — парсер и каноническая таблица цен тарифов (Энергия)

## Видео-механизм (кратко)

Кадр камеры захватывается так (все сетевые операции — в executor, не на
event loop):

1. `openCamera` (`0x30401`) → сервер отвечает `cameraSettings` (`0x2030401`):
   `videoHost`, `videoPort`, `videoToken`, `spropParameter` (SPS/PPS).
2. На `videoHost:videoPort` отправляется подписочная датаграмма
   `b"\x00\x00" + videoToken`.
3. Сервер стримит RTP/H.264 на тот же UDP-порт клиента; `rtp_stream.py`
   собирает IDR-кадр (одиночные NAL / STAP-A / FU-A) и декодит в JPEG через
   ffmpeg.
4. После захвата отправляется `closeCamera`, чтобы не копить лимит активных
   видео-сессий на сервере.
