## 1. Что это за проект

**Akvilon InHome** — интеграция для Home Assistant. Подключается по UDP-протоколу
к серверу здания ЖК «Reka» (застройщик Аквилон) и даёт владельцу квартиры:
камеры, калитки/домофоны, счётчики, статус сервера.

Два репозитория:
- **Приватный (разработка):** `git@github.com:Gakuzi/akvilon_home.git`
- **Публичный (HACS-релизы):** `https://github.com/Gakuzi/akvilon_home_hacs`

## 2. ПРИОРИТЕТ: безопасность и секреты

- Если встретишь личные данные (IP сервера здания, DeviceID, ServerID, PASS,
  SUID, видео-токен, имена жильцов) — НЕ распространяй их за пределы приватного
  репозитория и приватного контекста.
- Публичный репозиторий получает код ТОЛЬКО через скрипт `sanitize.sh` (чистит
  данные) — это делает релизер, не ты.
- НИКОГДА не публикуй в открытый доступ реальные секреты.

## 3. Жёсткие правила (не нарушать)

1. **Работай только в своей `feature/*`-ветке** приватного репозитория.
2. **Никогда не коммить прямо в `main`** публичного или приватного репо.
3. Перед началом: `git fetch --all --prune`, посмотри ветки, не занял ли кто-то
   твою. Один агент = одна ветка.
4. Изменения — небольшими, осмысленными коммитами: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`.
5. После правок ОБЯЗАТЕЛЬНО проверь:
   ```bash
   python3 -m py_compile *.py          # синтаксис
   ssh klim "docker restart homeassistant"
   ssh klim 'docker logs homeassistant --since 2m 2>&1 | grep -iE "akvilon|аквилон|ERROR"'
   ```
6. Готовое вливай в `develop` (приватный) через merge — НЕ сам в `main`.
7. Публикацию релиза делает владелец/релизер по `RELEASE_POLICY.md` — не ты.

## 4. Как начать работу (алгоритм)

```bash
# 1) В приватный репозиторий
cd /home/pi/homeassistant/custom_components/akvilon_home

# 2) Ознакомься
cat AGENTS.md INSTRUCTIONS.md 2>/dev/null | head -200

# 3) Актуализируйся
git checkout develop && git pull origin develop
git checkout -b feature/<твоя-задача>   # новая ветка от develop
```

Если репозитория нет локально — клонируй:
```bash
git clone git@github.com:Gakuzi/akvilon_home.git /home/pi/homeassistant/custom_components/akvilon_home
```

## 5. Правила параллельной работы

- Один агент — одна ветка. Не коммить в чужую.
- Перед `git pull` — закоммить или stash своё.
- Часто подтягивай `develop` в свою ветку, чтобы не расходиться:
  ```
  git checkout develop && git pull origin develop
  git checkout feature/my && git merge develop
  ```
- Не переписывай запушенную историю (`git push --force`) без разрешения.
- При конфликте — решай аккуратно в своей ветке.

## 6. Что сообщать при завершении (в отчёте)

1. Имя ветки + список изменённых файлов.
2. Что сделано и проверено (компиляция, журнал).
3. Что НЕ сделано / ограничения.
4. Готово ли к слиянию в develop (да/нет) и почему.

## 7. Версии и релизы (кратко)

- `vX.Y.Z` — стабильный релиз (main).
- `vX.Y.Z-betaN` — бета (develop).
- Релиз делает `scripts/sanitize.sh` + `scripts/release.sh` (см. RELEASE_POLICY.md).
- HACS подсасёт релиз по git-тегу и покажет уведомление об обновлении.

## 8. Полезные команды (работы на Raspberry Pi klim)

```bash
# Перезапуск HA
ssh klim "docker restart homeassistant"

# Журнал интеграции
ssh klim 'docker logs homeassistant --since 5m 2>&1 | grep -iE "akvilon|аквилон"'

# Установка последней версии из публичного релиза
ssh klim 'cd /home/pi/akvilon_home_hacs/scripts && ./install_from_github.sh latest'

# Все личные данные (для ревью)
grep -rn "127.0.0.1\|PASS_PLACEHOLDER\|0:0\|fec8df\|token_placeholder" . --include="*.py" --include="*.md"
```
